# 1.4 — Empty states with one primary CTA

**Phase:** 1 · Lazygit feel  
**Status:** Decisions locked — see [../../DECISIONS.md](../../DECISIONS.md)  
**Visual change:** Yes  
**Depends on:** 0.1 (Home copy must not point at Detail)  
**Primary surfaces:** selector/home, runs pane, monitor transcript empty,
workflows missing

## Problem

Empty views are technically correct and emotionally blank (“No runs yet”).
Lazygit/yazi empty states teach the next key.

## Goal

Every empty/waiting surface shows:

1. What this pane is
2. Why it is empty
3. **One** primary action with its key

## Inventory

| Surface | Empty cause | Primary CTA |
|---|---|---|
| Home workflows | no `*.toml` | show `.agents/jig/` path (key: `?` or path only) |
| Home runs | none for workflow | `r` new run |
| Home runs | none global | select a workflow · `r` |
| Monitor transcript | step not started | “Waiting for step to start” (no fake CTA) |
| Monitor transcript | step done, no output | “No transcript captured” |
| Monitor steps | loading | spinner + “Loading run…” |
| Review docs | none | error state + Esc |

## Locked decisions

| ID | Lock |
|---|---|
| B1 | Rewrite Detail-pointing empty Runs CTA |
| A1 | First workflow auto-selected — empty global runs rare |

## Item decisions

1. Exactly one emphasized CTA line per empty body.
2. Secondary hints dim, max one extra line.
3. No emoji / sticker badges.
4. Loading ≠ empty: keep spinner states distinct.

## Implementation sketch

- Shared `EmptyState{Title, Body, CTA}` renderer in `shared`.
- Replace ad-hoc empty strings in runs/selector/monitor transcript.
- Tests for CTA substrings on empty models; assert Detail never mentioned.

## Acceptance

- [ ] Empty Home runs never mentions Detail
- [ ] Empty workflows shows directory hint
- [ ] Transcript empty for pending step does not advertise search/filter keys as
      if content existed
- [ ] Footer bindings stay honest (no `enter open` when nothing to open)
