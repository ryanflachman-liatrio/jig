# 1.1 — Persistent status line

**Phase:** 1 · Lazygit feel  
**Status:** Proposed  
**Visual change:** Yes  
**Depends on:** 0.3 (footer status semantics)  
**Primary surfaces:** `internal/tui/monitor` view layout, shared styles

## Problem

Identity and health are scattered: run id in a breadcrumb, workflow maybe there,
gate status in the footer, costs in the Steps panel footer. Lazygit keeps a
stable identity strip you can glance at without decoding panel titles.

## Goal

Add a **one-row status line** above the footer (or as the left segment of a
two-segment footer) that always shows:

`run · workflow · step · state · tokens/cost`

## Decisions to lock

1. **Placement:** prefer a dedicated row between panels/gate and the keybinding
   footer — clearer than jamming into CompactHint.
2. **Fields (left→right):** short run id · workflow name · focused/current step ·
   run+gate state · optional tokens/cost when known.
3. **Truncation:** drop cost first, then shorten workflow, then step; never drop
   state.
4. **Update cadence:** same as existing live tick / event path — no new timers
   unless needed.
5. **Home screen:** optional lighter status (`N workflows · M runs`) — nice-to-have
   in this item, required in Monitor.

## Implementation sketch

- `statusLineView(width) string` on monitor model.
- Reserve height in vertical layout (`statusH := 1`).
- Pull cost/token from existing steps-panel total source so we do not duplicate
  accounting.
- Theme: reuse Marker/Dim/Error — no new colors unless Status needs a quiet bar
  background (prefer none).

## Acceptance

- [ ] Monitor always shows status line when height ≥ threshold (define min, e.g. 12)
- [ ] Pending gate state appears in status within one event cycle
- [ ] Narrow widths keep state visible
- [ ] Keybinding footer remains separate and still CompactHint-safe
