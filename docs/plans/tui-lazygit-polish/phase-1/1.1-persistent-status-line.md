# 1.1 — Persistent status line

**Phase:** 1 · Lazygit feel  
**Status:** Decisions locked — see [../../DECISIONS.md](../../DECISIONS.md)  
**Visual change:** Yes  
**Depends on:** 0.3 (footer owns state words)  
**Primary surfaces:** `internal/tui/monitor` view layout, shared styles

## Problem

Identity and health are scattered: run id in a breadcrumb, workflow maybe there,
gate status in the footer, costs in the Steps panel footer. Lazygit keeps a
stable identity strip you can glance at without decoding panel titles.

## Goal

One-row **status line** between panels/gate and the keybinding footer:

`run · workflow · step · tokens/cost` (+ LIVE / `N new` when relevant)

**State words stay in the footer** (C1) — do not duplicate `running` /
`awaiting review` on the status line.

## Locked decisions

| ID | Lock |
|---|---|
| C1 | Status = identity + cost; footer = state + keys |
| G1 | Short run id = 8 hex |
| G4 | Step field: pending gate’s step → else selected → else running |
| G5 | Unseen `N new` on status line only |
| C2 | LIVE / unseen live here so titles can slim (2.2) |

## Implementation sketch

- `statusLineView(width) string` on monitor model.
- Reserve `statusH := 1` in vertical layout.
- Pull cost/token from existing Steps total source (no double accounting).
- Truncation: drop cost first, then shorten workflow, then step; never drop run id.
- Theme: Marker/Dim only — no new colors; no bar background.
- Min height: hide status line only when terminal height &lt; 12 (document threshold).

## Acceptance

- [ ] Monitor shows status line when height ≥ 12
- [ ] Status never duplicates footer state words
- [ ] Pending-gate step wins step field when a gate is pending
- [ ] `N new` / LIVE appear on status when applicable
- [ ] Narrow widths keep run id + step readable
- [ ] Keybinding footer remains separate and CompactHint-safe
