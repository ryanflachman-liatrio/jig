# 1.3 — Command palette

**Phase:** 1 · Lazygit feel  
**Status:** Decisions locked — see [../../DECISIONS.md](../../DECISIONS.md)  
**Visual change:** Yes  
**Depends on:** 0.3, 0.4 (stable action inventory / leave rules)  
**Primary surfaces:** new `internal/tui/palette` (or `shared/palette`), root +
monitor integration

## Problem

Monitor+review key density is high. Single-key hotkeys should stay for the happy
path; the long tail should be searchable — k9s-style — without memorizing chords.

## Goal

A filterable command palette listing **currently available** commands with key
equivalents, runnable without memorizing chords.

## Locked decisions

| ID | Lock |
|---|---|
| E4 | Chord = **`ctrl+k` only** (no `:` in v1) |
| E5 | Drop stale “open runs…”; retarget Home / switch-run after 0.1 |
| D10 | `?` = reference · `ctrl+k` = run command · `ctrl+\` = help-agent (unchanged) |
| D1 | Help-agent IA not redesigned here |

## Item decisions

1. Contents: only enabled actions for current screen/focus (mirror footer SOT).
2. Destructive actions require the same confirm step as the keypath.
3. Presentation: centered overlay + filter input; Esc closes; Enter runs.
4. Does not replace hotkeys — show binding in a column.
5. Scope v1: Monitor + Home; review commands when review open.
6. Respect `CapturesText` (same rules as `?`).

## Implementation sketch

```text
type Command struct {
  ID      string
  Title   string
  Binding string // display only
  Enabled bool
  Run     func() tea.Cmd
}
```

- Build catalogs from the same enablement logic as footers.
- Reuse help-overlay compositor for centering.
- Tests: disabled omitted; running “reset step” triggers same msg as keypath.

## Acceptance

- [ ] `ctrl+k` opens palette from Monitor Steps/Transcript when not typing
- [ ] Filter narrows by title substring
- [ ] Executing a command equals the keybinding path (shared handler)
- [ ] Esc closes without side effects
- [ ] Palette listed in Global help
- [ ] No `:` binding in v1
- [ ] No “open runs…” dead command after 0.1
