# 1.3 — Command palette

**Phase:** 1 · Lazygit feel  
**Status:** Proposed  
**Visual change:** Yes  
**Depends on:** 0.3, 0.4 (stable action inventory / leave rules)  
**Primary surfaces:** new `internal/tui/palette` (or `shared/palette`), root +
monitor integration

## Problem

Monitor+review key density is high (`gg`, filters, expand-all, recovery verbs,
lifecycle chords…). Single-key hotkeys should stay for the happy path; the long
tail should be searchable instead of memorized — k9s `:` style.

## Goal

A fuzzy command palette (`:` or `ctrl+k`) listing **currently available**
commands with key equivalents, runnable without memorizing chords.

## Decisions to lock

1. **Chord:** `ctrl+k` globally when not capturing free text; `:` when not in a
   text field (same CapturesText rules as `?`). Prefer documenting both; ship
   `ctrl+k` first if `:` fights gate text.
2. **Contents:** only enabled actions for current screen/focus (mirror footer
   source of truth). Include destructive actions with confirm step.
3. **Presentation:** centered overlay list + filter input; Esc closes; Enter
   runs.
4. **Does not replace hotkeys** — palette shows the binding in a column.
5. **Scope v1:** Monitor + Home. Review commands appear when review open.

## Implementation sketch

```text
type Command struct {
  ID      string
  Title   string
  Binding string // display only
  Enabled bool
  Run     func() tea.Cmd
}
```

- Build catalogs per surface from the same enablement logic as footers.
- Reuse help overlay compositor pattern for centering.
- Tests: disabled commands omitted; running “reset step” triggers same msg as
  keypath.

## Acceptance

- [ ] Filter narrows by title substring
- [ ] Executing a command equals the keybinding path (shared handler)
- [ ] Esc closes without side effects
