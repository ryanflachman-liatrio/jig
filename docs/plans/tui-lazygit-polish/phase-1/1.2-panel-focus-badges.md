# 1.2 — Panel focus badges

**Phase:** 1 · Lazygit feel  
**Status:** Decisions locked — see [../../DECISIONS.md](../../DECISIONS.md)  
**Visual change:** Yes  
**Depends on:** — (pairs with 0.2)  
**Primary surfaces:** `internal/tui/shared` panel titles, monitor layout titles

## Problem

Focus is signaled mainly by Charple vs Iron border color. That works when you
already know the system; it is weak with three regions and long breadcrumbs.
Operators ask “where will `j` go?”

## Goal

Make focus legible from **title text** as well as the border:

- Focused panel: `[STEPS]`, `[TRANSCRIPT]`, `[GATE]`, later `[REVIEW]`
- Blurred panels: plain titles
- Badge width-stable enough that layout does not jump

## Locked decisions

| ID | Lock |
|---|---|
| C3 | Gate focused → `[GATE] · …`; blurred pending → `GATE · needs input` (no brackets) |
| E1 | Blurred pending gate keeps **Iron** border; badge/title carries attention |
| G8 | Badge is text, not color-only (a11y) |

## Item decisions

1. Badge vocabulary: uppercase short names in brackets (Lazygit-ish).
2. Combine with breadcrumbs: badge replaces the leaf role word when focused —
   `ab12 · feature › [STEPS]` not `… › Steps › [STEPS]`.
3. Exactly one region badged at a time (none while help modal steals chrome).
4. Narrow single-panel mode: badge still required.
5. Review badge deferred to 2.1 (`[REVIEW]`).

## Implementation sketch

- Title builders accept `focused bool` and inject badge via shared
  `FocusTitle(name string, focused bool) string`.
- Truncation (BreadcrumbTitle) must prefer keeping the badge over a long run id.
- Snapshot tests for focused vs blurred titles.

## Acceptance

- [ ] Exactly one region shows a `[NAME]` badge (or none under help modal)
- [ ] Tab cycles update badge + border together
- [ ] Truncation never strips badge while leaving a long run id
- [ ] Blurred pending gate uses unbracketed `GATE · needs input` + Iron border
- [ ] 2.1 documents `[REVIEW]` badge ownership
