# 0.3 — Context footer: only actions that work now

**Phase:** 0 · Happy path  
**Status:** Proposed  
**Visual change:** Yes (footer content; layout mostly unchanged)  
**Risk:** Low  
**Primary surfaces:** `internal/tui/shared` (`CompactHint`, bindings),
`internal/tui/monitor` (`compactHelpBindings`, `HelpSections`), runs/home
footers

## Problem

Footers either dump too many chords or truncate to `? more` so aggressively that
operators never learn the three keys they need. Disabled actions sometimes still
conceptually “exist” in muscle memory because neighboring screens advertise
different meanings for the same key (`r` = new run / reset / retry / finalize).

## Goal

Footer shows **only currently valid actions** for the focused region, ordered by
importance, with a stable discoverability escape hatch (`?` / `F1` → `more`).

## Decisions to lock

1. **Source of truth:** footer bindings = first help section for current focus
   (monitor already does this via `compactHelpBindings`) — extend the same
   contract to Home/Detail leftovers.
2. **Ordering:** primary verb first (enter/open/submit), then navigation, then
   secondary, then `more`. Never lead with quit.
3. **Atomic admission:** keep `CompactHint` behavior (never clip mid-binding).
4. **Remapped keys:** when the same physical key changes meaning, the footer
   label must change in the same Update cycle (`r reset` vs `r retry`).
5. **Width budget:** target ≤ terminal width; at 80 cols show ≥ 3 contextual
   actions + `more` when any contextual actions exist.

## Implementation sketch

- Inventory every `footerView` / `HintString` call site; replace ad-hoc lists
  with a shared `FooterBar{Status, Bindings}` helper if duplication hurts.
- Ensure lifecycle action `SetEnabled` paths stay the only gate for stop/reset/
  resume visibility (already tested — extend to Home).
- Add golden string tests at 80 and 120 columns for Steps / Transcript / Gate /
  Review-open / Home.
- Copy-edit help strings to verb+object (`open run`, not just `monitor`).

## Acceptance

- [ ] No footer advertises a disabled action
- [ ] At 80 columns, Monitor waiting-on-gate shows status + ≥2 gate actions + more
- [ ] Switching focus updates footer labels before next key is processed
- [ ] `?` / `F1` still opens the full overlay with sections
- [ ] Quit remains available in help overlay; optional in footer only if space

## Expected UI (after)

### Steps focus — running step selected

```text
  running  ·  s stop  ·  j/k select  ·  enter transcript  ·  ? more
```

### Steps focus — failed quiescent step

```text
  done  ·  r reset  ·  j/k select  ·  enter transcript  ·  ? more
```

### Transcript focus — follow paused

```text
  running  ·  f follow  ·  j/k scroll  ·  / search  ·  ? more
```

### Gate focus — recovery

```text
  step failed — recovery  ·  r retry  ·  g guide+retry  ·  s skip  ·  ? more
```

### Before (pain)

```text
  running  ·  s stop  ·  r reset  ·  ctrl+r resume  ·  j/k select  ·  enter …
             ↑ reset/resume shown even when not eligible, or truncated into noise
```
