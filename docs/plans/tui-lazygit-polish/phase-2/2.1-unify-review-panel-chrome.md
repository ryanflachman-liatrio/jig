# 2.1 — Unify review into Monitor panel chrome

**Phase:** 2 · Remaining friction  
**Status:** Decisions locked — see [../../DECISIONS.md](../../DECISIONS.md)  
**Visual change:** Yes  
**Depends on:** 0.4 (Esc ladder), 1.2 (badges)  
**Primary surfaces:** `internal/tui/review`, `internal/tui/monitor` review
embedding

## Problem

Opening the review workspace abandons Steps+Transcript grammar. Operators lose
spatial continuity: different layout, footer rules, leave keys. Lazygit expands
a panel; it does not replace the whole UI for a subflow.

## Goal

Review is a **mode of the content panel**, not a foreign screen:

- Keep Steps visible when width allows
- Right panel title becomes `[REVIEW] · doc · progress`
- Gate strip stays a stable one-line bar (contents may change)
- Footer uses the same CompactHint machinery

## Locked decisions

| ID | Lock |
|---|---|
| E2 | Gate bar **height stable** while review open (ADR 0002 no-reflow) |
| E3 | Steps \| Review only if width ≥ **160**; else full-width Review |
| A3/A4/C4 | Esc closes review → gate; does not leave Monitor |
| C3/1.2 | Focused review uses `[REVIEW]` badge |

## Implementation sketch

- Wide (≥160): Steps | `review.EmbeddedView` in transcript slot.
- Narrow (&lt;160): full-width review; Steps hidden until Esc.
- Keep EmbeddedView’s “no duplicate footer” contract; Monitor owns footer.
- Document list width clamps to panel inner width.
- Layout + Esc ladder tests; hunk nav still works at panel width.

## Acceptance

- [x] Width ≥ 160: Steps remain visible during review
- [x] Width &lt; 160: full-width review; Esc returns to gate (Steps restore)
- [x] Review uses shared Panel / BreadcrumbPanel chrome + `[REVIEW]` badge
- [x] Footer bindings match review.Help via CompactHint
- [x] Gate bar row count unchanged when opening/closing review
- [x] Diff hunk nav still works inside the panel width
