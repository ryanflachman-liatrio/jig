# 2.1 — Unify review into Monitor panel chrome

**Phase:** 2 · Remaining friction  
**Status:** Proposed  
**Visual change:** Yes  
**Depends on:** 0.4 (Esc ladder), 1.2 (badges)  
**Primary surfaces:** `internal/tui/review`, `internal/tui/monitor` review
embedding

## Problem

Opening the review workspace abandons the two-panel Steps+Transcript grammar.
Operators lose spatial continuity: suddenly a different layout, different footer
rules, different leave keys. Lazygit never replaces the whole UI for a subflow —
it expands a panel.

## Goal

Review is a **mode of the right-hand (or full-width) content panel**, not a
foreign screen:

- Keep Steps visible when width allows
- Right panel title becomes `[REVIEW] · doc · progress`
- Gate strip may shrink to a decision summary while workspace is open
- Footer uses the same CompactHint machinery

## Decisions to lock

1. **Wide layout:** Steps | Review workspace (documents+source as today, but
   inside panel chrome).
2. **Narrow layout:** full-width Review with breadcrumb back affordance; Steps
   hidden until Esc.
3. **Gate while reviewing:** collapse to one status row (`awaiting review · S
   finish`) rather than a second competing workspace.
4. **EmbeddedView:** already omits duplicate footer — keep single footer owner =
   Monitor.
5. **Badge:** `[REVIEW]` when workspace focused (from 1.2 vocabulary).

## Implementation sketch

- Stop replacing entire monitor body with unconstrained review view when wide.
- `review.EmbeddedView` sized to transcript panel slot.
- Document list width clamps to panel inner width.
- String/layout tests for wide vs narrow; Esc ladder tests from 0.4 still pass.

## Acceptance

- [ ] Wide: Steps panel remains visible during review
- [ ] Review uses shared Panel / BreadcrumbPanel chrome
- [ ] Footer bindings match review.Help and CompactHint
- [ ] Esc closes workspace to gate without leaving Monitor
- [ ] Diff hunk nav still works inside the panel width
