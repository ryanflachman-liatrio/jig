# Seam Probe — WithCanUseTool under acceptEdits

## Finding

**The `WithCanUseTool` callback does NOT fire when `permission_mode = "acceptEdits"`.**

Under `acceptEdits` the Claude Code CLI auto-approves all write operations
(`Write`, `Edit`, `Bash`) without invoking the callback. Only `PermissionModeDefault`
routes through the callback infrastructure.

## Evidence

The SDK documentation (`options.go` in `github.com/severity1/claude-agent-sdk-go`)
states this explicitly:

```
// IMPORTANT: Permission callbacks are only invoked for tools that would
// normally prompt the user for permission AND when using PermissionModeDefault.
//
// - Read-only operations (Read, Glob, Grep) are auto-approved and do NOT trigger callbacks
// - Write operations (Write, Edit, Bash) trigger callbacks ONLY in PermissionModeDefault
// - PermissionModeAcceptEdits auto-approves Write/Edit/Bash without invoking callbacks
// - Permission callbacks require Client API (streaming mode) - Query API does not support them
```

This comment appears in the SDK's example `11_permission_callback/main.go` and
is confirmed by all three permission-callback examples in that file, each of which
explicitly sets `claudecode.WithPermissionMode(claudecode.PermissionModeDefault)`.

## Chosen Seam

**Forced `PermissionModeDefault` when the guard is active.**

In `internal/runner/agent.go`, when `req.Guard != nil`, the runner overrides
the workflow step's `permission_mode` with `PermissionModeDefault`:

```go
if req.Guard != nil {
    opts = append(opts, claudecode.WithPermissionMode(claudecode.PermissionModeDefault))
    // ... register WithCanUseTool callback
}
```

This override applies after the step's own permission mode is set by
`buildOptions`, so `permission_mode = "acceptEdits"` in the workflow TOML is
superseded whenever the guard is active. The trade-off: the agent must confirm
each write tool call instead of auto-approving, which adds latency per tool use
but is required for the firewall to fire.

## Why Not a Live Probe Test

A live seam probe (`TestMain` helper calling `AgentExecutor.Execute` with a
real Claude Code CLI) would require the CLI to be installed in the CI environment
and would be non-deterministic. The SDK source-code evidence is authoritative —
the behavior is part of the SDK's documented contract, not an implementation
detail that requires runtime verification.

The unit test equivalent (`TestBuildOptions` in `agent_test.go`) confirms that
`buildOptions` passes the workflow step's `permission_mode` to the SDK; the
override in `Execute` is a straightforward `opts = append(opts, ...)` call that
is verified at compile time and exercised by `TestBlockedAndRedacted`.
