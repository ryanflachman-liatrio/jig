# Demo — Tier-1 firewall blocks secret write and redacts transcript

## What this demo proves

When the Tier-1 guard is active:
1. An agent attempting to `Write` a file containing an AWS key receives a denial
   reason from the SDK (the tool never executes).
2. The `transcript.jsonl` entry for that tool call has the key replaced with a
   redacted preview — no raw secret on disk.
3. `findings.jsonl` contains one `blocked` finding with the redacted evidence.

## Simulated scenario (unit-test driven)

Because a live workflow requires the Claude Code CLI, this demo is expressed as
a **scripted-channel unit test** that drives the same code paths a live run
would exercise. The test is `TestBlockedAndRedacted` in
`internal/runner/agent_test.go`.

### Script

```
AssistantMessage {
    ToolUseBlock{ToolUseID:"tu1", Name:"Write", Input:{
        "file_path": "config.txt",
        "content":   "aws_access_key_id = AKIAIOSFODNN7EXAMPLE"
    }},
    ToolUseBlock{ToolUseID:"tu2", Name:"Write", Input:{
        "file_path": "main.go",
        "content":   "package main\n"
    }},
}
ResultMessage{IsError: false}
```

The `captureStream` call has `req.Guard = sentinel.NewGuard(nil)` (outbound rule
disabled; secret-in-write rule active).

### Observed transcript entry (block 0 — Write with key)

The `Input` field of the first ToolUseBlock in the written transcript entry
contains the redacted form, not the raw key:

```json
{"file_path":"config.txt","content":"aws_access_key_id = [aws-key:…MPLE]"}
```

The raw string `AKIAIOSFODNN7EXAMPLE` does not appear in `transcript.jsonl`.

### Observed findings.jsonl entry

```json
{
  "ts": "2026-...",
  "run_id": "run1",
  "step_id": "impl",
  "iteration": 1,
  "tier": "guard",
  "monitor": "secret-in-write",
  "severity": "high",
  "action": "blocked",
  "detail": "tool input contains aws-key pattern: [aws-key:…MPLE]",
  "evidence": "tool:Write:tu1",

}
```

`captureReporter.findings[0]`:

```
Tier:        "guard"
Monitor:     "secret-in-write"
Severity:    "high"
Action:      "blocked"
Fingerprint: <same as findings.jsonl>
```

## What happens in a live run (not exercised here)

In a live run:
1. The SDK receives the agent's AssistantMessage with the Write tool_use.
2. The `WithCanUseTool` callback fires (guard forces `PermissionModeDefault`).
3. The callback calls `guard.Check("Write", input)` → denied.
4. The callback returns `NewPermissionResultDeny(reason)`.
5. The SDK injects a tool_result carrying the denial message back into the
   conversation — the agent receives the reason and may adapt.
6. `captureStream` processes the AssistantMessage: redacts the Input before
   writing to transcript, produces the finding, emits the SecurityFinding event.
