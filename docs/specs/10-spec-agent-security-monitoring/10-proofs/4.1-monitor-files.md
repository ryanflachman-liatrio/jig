# Monitor Agent Files

Three tools-off, Haiku monitor agents are present at:

| File | Monitor name | Model | Tools |
|------|-------------|-------|-------|
| `examples/agents/monitors/prompt-injection.md` | `prompt-injection` | haiku | (none) |
| `examples/agents/monitors/stuck-loop.md` | `stuck-loop` | haiku | (none) |
| `examples/agents/monitors/exfil-pattern.md` | `exfil-pattern` | haiku | (none) |

## Validation

All three files parse as valid `agent_file` triples under `jig validate`:

```
$ go run ./cmd/jig validate test_monitors.toml
ok: "monitor-validation" v1.0.0 — 3 step(s)
```

Each file has valid YAML frontmatter (`---`/`---` delimiters, `name:`, `model:`)
and a prompt body. The empty `tools:` field means tools-off — the monitor agent
runs with no tool access, which is required for safe, budget-bounded classification.

## Structured output contract

Each monitor returns JSON with three fields:

```json
{
  "flagged": true,
  "severity": "high",
  "detail": "human-readable description of what was found"
}
```

The supervisor's `MonitorDispatcher.Dispatch` maps this to `MonitorResult{Flagged, Severity, Detail}`.
